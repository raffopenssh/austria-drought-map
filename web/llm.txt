# groundwater-at — Austrian Drought & Water-Stress Risk
# LLM / sibling-service reference

Base URL:    https://groundwater-at.exe.xyz/
Service slug: groundwater-at
License:     CC-BY-4.0
CORS:        all origins allowed (read-only GETs)

## What this dataset is

A composite drought / water-stress risk model for all ~2,100 Austrian
municipalities (Gemeinden). It fuses Copernicus EDO Combined Drought Indicator,
eHYD groundwater & surface-flow station trends, GeoSphere precipitation,
WISE water-quality status, INSPIRE soil permeability, and e-control hydropower
exposure into a 0–1 risk_score (low/medium/high). Interactive map at the base URL.

Granularity: per Gemeinde (municipality). Keyed on the official 5-digit
Statistik Austria gemeinde_code.

## Sibling-service integration endpoints (/llm/)

Implements the Austrian Cadastre "Integration Spec for Sibling Data Services"
(https://cadastre-process-api.exe.xyz/api/v1/docs/llm.txt?section=integration).

Our headline metrics are per-municipality, so every per-KG answer maps UP from
kg_code to its gemeinde_code (resolved once through the canonical /api/v1/lookup
EDM register, cached in data/kg_to_gemeinde.json) and returns the Gemeinde-level
block; every KG inside a Gemeinde returns the same metrics. No local fuzzy
matching of place names.

In addition we carry three POINT datasets — groundwater stations, hydropower
plants and WISE water-quality sites — each snapped ONCE to its Katastralgemeinde
(and parcel) via the cadastre's POST /api/v1/spatial/points (exact
point-in-polygon). Those observations are returned under 'points', grouped by
KG, with each station's full annual history and (when confident) its parcel_id.
KG-level roll-ups (station/plant/site counts, mean GW trend, total MW, #at-risk)
are folded into 'metrics'.

  GET /llm/kg/{kg_code}            drought/water-stress metrics for one KG
  GET /llm/kg/{kg_code}.json       (alias; JSON is the only format)
  GET /llm/kgs?codes=a,b,c         batch (<=500 codes) -> {"results":[...]}
  GET /llm/manifest.json           coverage + metrics schema (crawl entry point)
  GET /llm/covered_kgs.json        array of every kg_code we can answer (7,545)

404 with {"kg_code":"...","error":"no_data"} when a KG is outside our coverage.

## Notes for consumers

- kg_code and gemeinde_code are different numbering systems; we never mix them.
  All codes are 5-character strings — keep leading zeros, do not cast to int.
- Codes are resolved through the cadastre API's /api/v1/lookup (BEV EDM /
  Statistik Austria), the shared source of truth — we maintain no private
  name/code table.
- Version via as_of / updated_at, not by renaming keys.
